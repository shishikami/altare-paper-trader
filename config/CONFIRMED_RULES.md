# 本地 paper 交易规则：部分已确认，仍禁止启用

这里只记录已授权公开的交易参数，不含账户、身份、凭据或旧实验数据。
这四项确认不等于其他参数确认，更不等于服务器部署、启动或任何实盘授权。

## 已确认的四项

| 规则 | 配置字段 | 值 |
|---|---|---|
| 初始本地模拟现金（USD，不是交易所余额） | `initial_cash_usd` | 4800 |
| 日亏阈值，达到即熔断 | `daily_loss_usd` | 96 |
| 单笔按止损计划的最大损失 | `max_planned_loss_usd` | 48 |
| BTC 与 ETH 合计持仓上限，按初始本金的 80% | `max_holdings_initial_fraction` | 0.80，即固定 3840 USD |

## 执行语义与保守保护

### 48 USD 是计划风险，不是订单金额，也不是最大实际亏损保证

每次新买入先计算数量（向下保留八位）、预计成交价、固定止损触发价：

```
entry = 参考行情价 × (1 + 模型买入滑点)
stop_trigger = entry × (1 - 暂定止损比例)
stop_execution = stop_trigger × (1 - 模型卖出滑点)
planned_loss = 数量 × (entry - stop_execution)
               + 数量 × entry × 买入手续费率
               + 数量 × stop_execution × 卖出手续费率
```

`planned_loss > 48` 拒绝整笔买入，等于阈值允许继续检查其他限制；不会只检查
订单金额或忽略交易成本，也不会自动扩大订单到“用满”48。接受的 paper fill
记录 `planned_loss_usd` 和 `stop_price`，持仓保存同一个触发价。策略不能修改风控。
止损比例、手续费和滑点仍只是未确认模型。跳空、断网、轮询延迟、真实流动性变化
可能让实际/模拟实现损失超过计划；48 不是保本或最大损失承诺。

### 合计持仓按当前估值，不按原买入成本

每次买入使用两币的当前合格报价，检查买后总持仓当前市值，并同时满足：

- 固定初始预算：`4800 × 80% = 3840`，盈利后也不提高这个美元上限；
- 更保守的当前权益保护：不超过扣除该笔手续费和模型滑点后的当前权益的 80%；
- 其他仍存在的更严子约束；买入现金必须覆盖成交额及买入手续费。

因此最终上限取这些限制中最严的一项；权益下降时不能仍机械按3840加仓。
持仓自然上涨越界时仅拒绝新增敞口，不因这条规则暗自卖出或强制清仓。
独立止损/策略退出仍可降低持仓。80%约束是买入前检查，不保证价格变动之后持续
保持80%比例，也不是授权自动再平衡。

### 96 USD 日亏口径及仍待确认的细则

采用已有保守实现：Asia/Shanghai 自然日，组合权益=现金+全部当前持仓估值；
相对日初权益计算净亏损，包含已实现和未实现盈亏、买卖手续费及成交滑点。
`day_open - current_equity >= 96` 即持久熔断新增买入，当日回升/进程重启不解除；
不把96仅当作“已实现亏损”，不因重启重设日初本金。每笔模拟成交后再次检查。
保护性卖出成本可能使已触及96的亏损进一步增加，96不是最大实际亏损保证。

目前实现只停止增加风险，允许策略/止损减仓，不自动全仓卖出；到下一个北京时间
自然日才重置当日熔断。跨日开盘权益取上一份持仓估值，首次新报价的亏损归入新日，
不悄悄丢掉隔夜跳空亏损；这不是精确的午夜 NAV。该口径、减仓与次日恢复政策
作为保守暂定细则明确记录，尚未获得逐项确认，不能因此打开总开关。

## 未确认项：全部保持原来的更严限制，不擅自放宽

- 事件/AI继续禁用，无外部AI密钥或可信事件输入；无交易所私有交易通道。
